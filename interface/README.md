# Solver interface

The simulation framework in this repository never touches a solver internal. It
loads two shared libraries and calls the ABI in
[`solver_abi.h`](solver_abi.h):

```
sim/framework.py ──► sim/solvers.py (ctypes) ──► libanymal_nmpc.so   (RTI NMPC)
                                             └─► libanymal_nmhe.so   (RTI MHE)
                                                      │
                                                      └─ c/anymal_models.h
                                                         generated by
                                                         model/anymal_srbd.py
```

Each library is a single translation unit that

1. includes the generated SRBD model header (dynamics, Jacobians, constraints,
   outputs, all with common-subexpression elimination),
2. fixes the problem dimensions at compile time (`N`, `M`, `nx`, `nu`, `nc`, …),
3. wraps a real-time-iteration solver kernel and exposes the ABI above.

## What is withheld, and why

The two kernels are a constrained real-time-iteration NMPC solver and its
moving-horizon-estimation variant, developed as an extension of my master's
thesis on SLQP-MPC. That work is ongoing and not yet published, so the
algorithms, their source, and the wrapper translation units that embed them are
not part of this repository. What is public is everything the kernels are used
*for*: the reduced-order model and its generator, the gait and foothold
planner, the proprioceptive measurement model with contact gating, the plant,
the whole closed loop, and the experiments that produced the results in
[`../docs/report.pdf`](../docs/report.pdf).

Measured solver performance is reported in the study (per-cycle wall times,
memory footprint, horizon scaling) because it characterises what the framework
runs on; the mechanisms that produce those numbers are not described.

## Dropping in a different solver

The ABI was deliberately kept small and conventional, so a substitute is a
single afternoon of C glue and no Python changes. What a replacement must
provide:

| requirement | why the framework needs it |
| --- | --- |
| RTI-style split: a `prepare` phase that can run before the state arrives and a `feedback` phase that maps the fresh state to the first input | the loop applies `u0` within a fraction of a millisecond of the estimate and overlaps the rest with plant motion (report Sec. VI) |
| nonlinear stage inequality constraints, evaluated per stage | friction pyramids, normal-force bounds and attitude bounds must be enforced inside the solve, not clipped afterwards |
| per-stage parameters, changing every sample | foot positions and contact flags differ per stage and shift with the gait schedule |
| warm start with a one-stage shift | the horizon spans contact switches; without the shift each switch costs extra iterations |
| a constrained MHE with estimated disturbance inputs, an arrival cost, and access to the newest-node estimate | the estimator returns the state *and* the disturbance wrench the controller feeds forward |

`acados` satisfies all of these (`ocp_nlp` for the controller, its MHE
formulation for the estimator); the model header generated by
`model/anymal_srbd.py` can be re-emitted as CasADi expressions from the same
SymPy source with a few lines of change, since the script already builds the
symbolic dynamics, constraints and outputs before printing C.

Two conventions are worth repeating because they are easy to get wrong:

* **Stage parameters must reach the model evaluation of their own stage.** The
  controller's constraint rows and input Jacobians depend on which feet are in
  contact at that stage; routing a single parameter set to all stages silently
  removes the contact schedule from the prediction.
* **Gated measurement rows must be zero rows, not small rows.** The estimator's
  output weight is constant, so a foot that is not in settled stance is removed
  by multiplying its rows (residual *and* Jacobian) by zero inside the model —
  see `h_nmhe` in `model/anymal_srbd.py`.
